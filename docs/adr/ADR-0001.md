# ADR-0001: Ethereum PoS con Besu y Teku

- **Fecha:** 2026-10-13
- **Estado:** Aceptado en diseño; ejecución sujeta a validación G0/G1.

## Contexto
Se desea aprender gas, validadores, EVM, depósitos y finalidad; Fabric no implementa ese modelo nativo.

## Alternativas consideradas
PoA/QBFT con Besu; Hyperledger Fabric; desarrollo de un consenso propio; Ethereum PoS con EL/CL.

## Decisión
Se elige Ethereum PoS privado: Besu para ejecución y Teku para consenso; forks, imágenes y compatibilidad de red propia se fijarán tras G0.

## Consecuencias y riesgos
Mayor fidelidad didáctica, pero dos redes P2P, un génesis EL/CL coordinado y mayor consumo de RAM. No equivale a Ethereum Mainnet.

## Prueba de aceptación
Levantar devnet con 7 validadores; observar propuestas, attestations y finalidad y registrar versiones, imágenes y hashes.

## Reversibilidad
Cualquier cambio que afecte los parámetros del génesis exige un nuevo ADR, reconstrucción de devnet y, si la red definitiva ya fue lanzada, plan explícito de migración.
